# 90 天成长追踪系统产品需求

- 状态：当前需求基线
- 更新日期：2026-08-20
- 适用版本：1.0

本文档描述当前已经确认并实现的产品范围。历史设计稿或实施计划与本文冲突时，以本文和用户最新明确要求为准。

## 1. 产品目标

将新员工 90 天培养计划数字化，让新人清楚完成“学、练、干”，让导师只处理自己负责新人的实践确认，让主管快速检索并查看所有新人进度，让管理员集中维护人员、账号、关系、任务与审计。

系统优先保证：

1. 进度和确认状态正确。
2. 角色职责清晰且服务端权限不可绕过。
3. 任务、天数、人员和关系可以维护。
4. 新人、导师和主管能够以较低操作成本完成日常工作。

## 2. 使用角色

### 2.1 新人（TRAINEE）

- 在登录页输入工号、姓名和密码自助注册，或使用管理员创建的账号。
- 只查看自己的培养进度。
- 查看所有启用的 D1、D2、D3、D4、Dall 任务。
- 完成或撤回 Learn。
- 分别提交或撤回尚未被导师确认的 Action、Drill。
- 填写学习反馈和给导师的留言。
- 查看导师留言及确认历史。

### 2.2 导师（MENTOR）

- 只查看管理员当前分配给自己的新人。
- 首页查看负责新人、截至今日进度、逾期与待确认数量。
- 待确认队列只包含新人已经主动提交、尚未确认的 Action 或 Drill。
- 分别确认或撤销确认 Action、Drill。
- 为负责新人填写导师留言，并查看新人留言。
- 不编辑任务库，不查看未分配新人。

### 2.3 主管（SUPERVISOR）

- 查看全部新人及其进度。
- 按姓名或工号搜索新人。
- 进度页面保持只读。
- 不处理 Action/Drill 确认，不写导师留言，不编辑任务，不把导师作为进度对象展示。

### 2.4 管理员（ADMIN）

- 查看全部新人，并按姓名或工号搜索。
- 调整全局培养计划总天数，范围为 1–365 天，每次增加或减少 1 天。
- 新增、编辑、启用或停用新人档案。
- 创建账号、重置密码、启用/停用账号和配置角色。
- 维护导师/主管与新人的有效关系。
- 新增、编辑、启用、停用任务。
- 预览并应用 Excel 任务导入。
- 查看审计日志。
- 可在必要时对任意新人代操作进度和确认。

### 2.5 角色约束

- TRAINEE 角色不能与 ADMIN、SUPERVISOR、MENTOR 同时分配给同一账号。
- ADMIN、SUPERVISOR、MENTOR 可按岗位需要组合，并通过角色视角切换进入对应首页。
- 禁用账号不能查看或修改业务数据。
- 前端可按角色隐藏操作，但所有读写权限必须在服务端使用实时账号、角色和关系再次校验。

## 3. 培养任务规则

### 3.1 任务范围

- 任务包含 Day、Stage、Dimension、任务说明、Action、Drill、Milestone、资料链接和排序。
- Stage 为 P1–P4；Dimension 为 D1、D2、D3、D4、Dall。
- 每位新人查看所有启用任务，不按重点分组裁剪任务。
- 新人的 Focus Group 只用于重点标识、筛选和重点完成率。
- 未来任务可提前查看和完成。

### 3.2 培养天数

- 默认总天数为 90 天。
- 管理员在人员管理页顶部统一增加或减少天数，不在每一个任务日中放置天数调整按钮。
- 总天数允许 1–365 天，并使用 revision 防止多人同时修改时静默覆盖。
- 当前培养日默认按“今天 − 培养开始日期 + 1”计算，可由管理员为单个新人覆盖。

### 3.3 Learn、Action、Drill

- Learn 由新人直接完成或撤回，不需要导师确认。
- Action 和 Drill 是互相独立的实践项。
- 新人点击某个 Action/Drill 的“完成并提交”后，对应项目才进入导师待确认队列。
- 新人未提交时，导师端不得出现该项目。
- 新人可撤回尚未被导师确认的提交；已经确认的提交不能由新人直接撤回。
- 导师只能确认自己负责新人已经提交的对应项目。
- 导师确认后，该项目从待确认队列移除；撤销确认后保留历史并恢复为已提交待确认状态。

## 4. 进度与展示

- 展示总学习完成率、截至今日完成率、Action 确认率、Drill 确认率、当前培养日和重点方向完成率。
- 总学习完成率分母为全部启用任务，不受 Focus Group 影响。
- Action/Drill 分母只包含对应内容非空的启用任务。
- 空分母显示“暂无任务”，不能显示误导性的 0%。
- 逾期任务为 `task.day < currentDay && !learnDone`。
- 已完成状态使用独立绿色背景或状态区域，完成标记放在任务卡右侧，不与 P1 或维度标签混放。
- 任务列表支持阶段、维度、状态和关键字组合筛选，筛选状态写入 URL。

## 5. 留言与确认历史

- 新人可填写学习反馈和给导师的留言。
- 导师可填写给新人的导师留言。
- 新人和负责导师都能看到双方留言。
- 主管和管理员可只读查看留言；管理员可按权限代写导师留言。
- 每次 Action/Drill 确认和撤销确认生成不可变 ConfirmationEvent。
- 进度和留言写入生成审计 before/after 快照。

## 6. 搜索与工作台

### 6.1 导师工作台

- 只列出分配新人。
- 显示进度摘要、风险、逾期和待确认数量。
- 右上角待处理数量等于已提交且未确认的 Action/Drill 总数。
- 待确认页明确显示新人、任务日、实践类型和内容，可逐项确认。

### 6.2 主管工作台

- 只以新人为管理对象，不展示导师进度。
- 默认列出所有启用新人。
- 提供始终可见的姓名/工号搜索。
- 不显示确认、打卡、写导师留言或编辑任务按钮。

### 6.3 管理员人员页

- 顶部展示全局培养天数加减控件。
- 新人列表支持姓名/工号搜索。
- 人员编辑、账号角色、负责关系、任务库、Excel 导入和审计使用独立管理入口。

## 7. 注册与登录

- 登录标识为工号，密码使用 bcrypt cost 12 哈希。
- 登录页提供“登录”和“注册”两个页签。
- 自助注册必填工号、姓名、密码；工号最长 64 字符，姓名最长 100 字符，密码 8–1024 字符。
- 工号必须同时在 User.username 和 Trainee.employeeId 中唯一。
- 注册创建 TRAINEE-only 账号、新人档案和审计记录，默认 Focus Group 为 D1、培养开始日期为注册当天。
- 注册成功后返回登录页并预填工号，不自动暴露会话或密码。
- 管理员 seed 密码只从环境变量读取；系统没有默认生产密码。

## 8. Excel 导入

- 管理员上传 `.xlsx` 后先执行预览，预览不写数据库。
- 预览输出新增、更新、停用候选、跳过、警告和错误；存在错误时禁止应用。
- 导入使用 StableImportKey 保持任务 ID 稳定，避免重新导入导致历史进度丢失。
- 应用导入必须明确确认，并在单个数据库事务中完成；失败整批回滚。
- 上传校验包括压缩包大小、ZIP 条目数、解压大小、行列数、单元格数量和单格长度。
- 内部资料链接只作为外链保存和展示，服务器不代理、抓取或执行链接内容。

## 9. 管理与审计

- 人员、账号、关系和任务默认使用启用/停用，不直接破坏历史数据。
- 高风险管理操作要求显式确认。
- 关系包含类型、主关系、启用状态、开始日期和结束日期；权限按业务日期判断是否有效。
- 账号禁用、角色撤销或关系失效后，旧会话不得继续执行原权限操作。
- 登录、注册、进度、确认、任务、关系和导入等关键操作进入审计日志。

## 10. 非功能需求

### 10.1 安全

- 不在源码、日志、健康接口或错误页面暴露密码、连接串、密钥和内部异常。
- `.env`、数据库备份、运行时上传、真实人员数据和部署产物不得提交 Git。
- 数据库只允许应用和受控运维访问，不开放公网 5432。
- 公网部署必须使用 HTTPS；明文 HTTP 只允许受信内网临时测试。

### 10.2 数据一致性

- 关键写操作使用数据库事务。
- `TaskProgress(traineeId, taskId)` 唯一。
- 已确认实践必须保持 submitted 状态。
- Prisma 迁移只向前应用；生产迁移前必须生成数据库备份。

### 10.3 可维护性

- 高频名称、颜色、角色、菜单、风险和进度规则集中在 `src/config`。
- 页面不直接实现权限公式或进度统计。
- Prisma 查询位于 repository/service 层，写操作通过 server actions 调用服务。
- 修改数据模型必须附带迁移与测试。

### 10.4 可用性与兼容性

- 中文优先，表单和操作反馈必须可理解、可恢复。
- 支持常用桌面宽度，并适配平板和手机单列任务卡。
- 交互控件具备可访问名称、键盘操作和必要的状态播报。
- 健康接口在数据库可用时返回 HTTP 200，数据库故障时返回 HTTP 503。

## 11. 部署要求

- 支持 Docker Compose：PostgreSQL 健康后执行一次性迁移，再启动非 root standalone 应用。
- 支持普通 Node.js/systemd 服务器，但同样必须先构建、备份、迁移并执行健康检查。
- 支持 Railway 私有 GitHub 部署和预部署迁移。
- 应用默认端口 3000，可通过受控防火墙或反向代理开放。
- 生产升级必须记录源码版本、迁移、备份和健康检查结果。

## 12. 验收标准

发布版本至少满足：

1. 新人未提交 Action/Drill 时，导师待确认数量不增加。
2. 新人提交单个实践后，只有负责导师看到对应一项待确认。
3. 导师确认后该项从队列移除，确认历史存在。
4. 主管能搜索任意新人，但不能确认、打卡、写导师留言或编辑任务。
5. 导师看不到未分配新人，新人看不到其他新人。
6. 新人和导师互相看得到留言。
7. 管理员可搜索新人并在页面顶部增加或减少总培养天数。
8. TRAINEE 不能与管理类角色组合保存。
9. 自助注册使用唯一工号创建新人账号，冲突时不产生半成品数据。
10. Lint、TypeScript、单元/集成测试、Prisma 校验和生产构建通过。
11. 全部迁移能在空的 PostgreSQL 16 测试库顺序应用。
12. `/api/health` 在应用和数据库正常时返回 200。

## 13. 不在当前范围

- 短信、邮件验证码和企业通讯录自动同步。
- 找回密码自助流程；当前由管理员重置。
- 实时聊天、社交动态和复杂多级审批。
- 自动抓取、下载或 AI 解析内部资料链接。
- 重型 BI、数据仓库和跨组织多租户。
- 认证矩阵、Milestone 独立页面和数据导出入口。
- 将真实人员数据或内部工作簿公开发布。
